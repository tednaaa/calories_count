# 04 — Калькулятор нормы калорий

Считается один раз при первом запуске, дальше доступен в настройках. Результат — одно число `targetKcal`, которое показывается на главной как цель дня.

## Формула

**Mifflin-St Jeor** — текущий стандарт де-факто, точнее устаревшей формулы Харриса—Бенедикта для современных популяций.

Базовый обмен (BMR), ккал/сутки:

```
мужчины:  BMR = 10 × вес(кг) + 6.25 × рост(см) − 5 × возраст + 5
женщины:  BMR = 10 × вес(кг) + 6.25 × рост(см) − 5 × возраст − 161
```

Полный суточный расход:

```
TDEE = BMR × коэффициент активности
```

| Уровень           | `ActivityLevel` | Коэф. | Описание для интерфейса                     |
| ----------------- | --------------- | ----- | ------------------------------------------- |
| Сидячий           | `sedentary`     | 1.2   | Офис, тренировок нет                        |
| Лёгкая активность | `light`         | 1.375 | Тренировки 1–3 раза в неделю                |
| Умеренная         | `moderate`      | 1.55  | Тренировки 3–5 раз в неделю                 |
| Высокая           | `high`          | 1.725 | Тренировки 6–7 раз в неделю                 |
| Очень высокая     | `veryHigh`      | 1.9   | Физическая работа или две тренировки в день |

Цель:

| Цель             | `Goal`     | Поправка | Ожидаемый темп |
| ---------------- | ---------- | -------- | -------------- |
| Похудение        | `cut`      | −20 %    | ≈ −0.5 кг/нед  |
| Мягкое похудение | `cutMild`  | −15 %    | ≈ −0.35 кг/нед |
| Поддержание веса | `maintain` | 0 %      | —              |
| Мягкий набор     | `bulkMild` | +10 %    | ≈ +0.2 кг/нед  |
| Набор массы      | `bulk`     | +15 %    | ≈ +0.3 кг/нед  |

Темп посчитан из того, что килограмм жировой ткани — примерно 7700 ккал: дефицит 500 ккал/сутки ≈ 0.45 кг в неделю.

## Реализация

```ts
// src/entities/profile/lib/calories.ts

const ACTIVITY: Record<ActivityLevel, number> = {
	sedentary: 1.2,
	light: 1.375,
	moderate: 1.55,
	high: 1.725,
	veryHigh: 1.9,
};

const GOAL: Record<Goal, number> = {
	cut: 0.8,
	cutMild: 0.85,
	maintain: 1,
	bulkMild: 1.1,
	bulk: 1.15,
};

/** Нижняя граница безопасности, ниже которой норму не опускаем */
const FLOOR: Record<Sex, number> = { male: 1500, female: 1200 };

export function calcBmr(
	p: Pick<Profile, "sex" | "weightKg" | "heightCm" | "birthDate">,
): number {
	const base = 10 * p.weightKg + 6.25 * p.heightCm - 5 * currentAge(p.birthDate);
	return base + (p.sex === "male" ? 5 : -161);
}

export function calcTdee(
	p: Pick<Profile, "sex" | "weightKg" | "heightCm" | "birthDate" | "activity">,
): number {
	return calcBmr(p) * ACTIVITY[p.activity];
}

export function calcTarget(
	p: Pick<
		Profile,
		"sex" | "weightKg" | "heightCm" | "birthDate" | "activity" | "goal"
	>,
): number {
	const raw = calcTdee(p) * GOAL[p.goal];
	return Math.max(FLOOR[p.sex], Math.round(raw / 10) * 10);
}
```

Результат округляется до десятков — точность формулы этого не хуже, а «1847 ккал» создаёт ложное впечатление аптечной точности.

Нижняя граница `FLOOR` нужна для лёгких людей на агрессивном дефиците: формула способна выдать 1100 ккал, и такую цель показывать не стоит. Если граница сработала, интерфейс сообщает об этом явно: «Расчёт дал меньше безопасного минимума, норма поднята до 1500 ккал».

## Валидация ввода

| Поле    | Диапазон   |
| ------- | ---------- |
| Возраст | 14–100     |
| Рост    | 120–230 см |
| Вес     | 30–300 кг  |

Все поля обязательны. Возраст не вводится, а считается из даты рождения: поле `type="date"` открывает системный выбор даты, и через год норму не надо править руками. Числовые поля — с `inputmode="numeric"`, чтобы на телефоне открывалась цифровая клавиатура. Вес — с `inputmode="decimal"` и точностью до десятых: колебания в полкило и есть то, что видно на графике веса. Русская клавиатура ставит запятую, поэтому разбор принимает и запятую, и точку.

## ИМТ и нормальный вес

ИМТ = вес / рост² (рост в метрах). Категории ВОЗ для взрослых: меньше 18,5 — недостаточный вес, 18,5–24,9 — норма, 25–29,9 — избыточный вес, от 30 — ожирение. От пола и возраста они не зависят.

Строка «ИМТ 26,2 — избыточный вес, норма для 180 см: 60–81 кг» стоит в онбординге, под формой профиля и в блоке «Вес» на экране «Статистика». Диапазон — тот же ИМТ 18,5–24,9, переведённый в килограммы для роста человека: это понятнее голого индекса.

**До 18 лет категории нет.** У подростков ИМТ оценивают по центильным таблицам ВОЗ с учётом возраста и пола, а профиль пускает с 14 лет. Взрослая категория здесь была бы просто неверной, поэтому показывается только число и пометка про таблицы.

ИМТ не отличает жир от мышц: у тренированных людей он завышен. Поэтому это справка рядом с весом, а не цель и не основа для нормы.

## Ручное переопределение

В настройках можно ввести своё число вместо расчётного. Тогда `targetOverridden = true`, и `targetKcal` перестаёт пересчитываться при изменении веса или активности. Рядом остаётся расчётное значение для сравнения и кнопка «Вернуть расчётное», сбрасывающая флаг.

## Пересчёт при изменении веса

Если `targetOverridden === false`, `targetKcal` пересчитывается автоматически при любом изменении профиля.

Изменение `weightKg` дополнительно пишет запись в `weightLog` за текущую дату (существующая запись за эту дату перезаписывается). Обратное тоже верно: вес, записанный на экране «Статистика», становится `profile.weightKg` и пересчитывает норму.

## Калибровка по весу

Формула даёт стартовое число, а не истину: коэффициент активности — это пять грубых ступеней, и попадание между ними обычное дело. Правильный способ уточнить норму — не считать точнее, а сверить расчёт с фактом.

Цикл такой: держать норму 3–4 недели → сравнить изменение веса с ожидаемым из расчёта 7700 ккал на килограмм → подвинуть норму. Сравнение считает экран «Статистика», блок «Вес».

Счёт:

- темп веса — наклон прямой по методу наименьших квадратов через все замеры за 28 дней; он устойчивее, чем «последний минус первый», и не боится пропусков;
- среднее съеденное — только по дням с записями и без сегодняшнего, ещё не законченного дня;
- ожидаемый темп = (среднее съеденное − расчётный расход) × 7 / 7700 кг в неделю, где расчётный расход — формула плюс поправка прошлого уточнения;
- реальный расход = среднее съеденное − наклон × 7700;
- погрешность расхода = σ / √Σ(t − t̄)² × 7700, где σ — разброс замеров вокруг прямой, не меньше 0,5 кг, а при меньше чем пяти замерах — типичные 0,7 кг.

Вывод появляется при трёх замерах, разнесённых хотя бы на 14 дней, и 14 днях с записями еды. Если еда записана меньше чем за 70 % дней, рядом предупреждение: недописанные дни занижают съеденное и вместе с ним расход.

Под выводом — «Уточнить норму»: три строки объяснения («вы ели… вес шёл… а расчёт ждал…», «значит, реальный расход…», «для цели… норма…») и кнопка «Поставить N ккал». Нажатие сохраняет поправку к расходу `tdeeCorrectionKcal = реальный расход − расход по формуле` и дату `calibratedAt`. Новая норма = (расход по формуле + поправка) × поправка цели, не ниже безопасного минимума. Норма при этом остаётся расчётной: новый вес и смена цели продолжают её пересчитывать, а в настройках она подписана «Посчитана по профилю и уточнена по весу» с кнопкой «Сбросить уточнение».

Кнопки нет, пока:

- профилю меньше 14 дней — первые недели диеты вес уходит вместе с водой, и расход выходит завышенным;
- с прошлого уточнения не прошло 28 дней — вместо кнопки «Следующее уточнение — через N дней»: окно расчёта должно целиком лечь на новую норму;
- замеров за 28 дней меньше восьми — при меньшем числе погрешность расхода больше одного шага нормы;
- еда записана меньше чем за 70 % дней;
- новая норма отличается от текущей меньше чем на 50 ккал — тогда «норма уже точная».

**За раз норма сдвигается не больше чем на 250 ккал.** Одна неудачная неделя не должна дёргать норму на полтысячи; если разница больше, остаток доедет при следующем уточнении, и интерфейс говорит об этом прямо. Без паузы в 28 дней шаг ничего бы не ограничивал: три нажатия подряд сдвинули бы норму на 750 ккал.

**Почему это подходит каждому.** Сравнение идёт по собственным записям человека, поэтому постоянная привычка недописывать еду гасится сама: норма получается в тех же «записанных» калориях. Сбивают расчёт только пропуски и дни, записанные наполовину, — это и отсекают условия выше. Раскрывающийся пункт «Почему это работает» пересказывает это человеческим языком.

Так калибровка опирается на **одно измерение вместо двух оценок**. Норма сама впитывает и нерегулярные прогулки, и разницу между формулой и конкретным обменом веществ.

**Уровень активности выбирается по среднему за неделю, а не по лучшему дню.** Один большой выход раз в неделю — это несколько сотен килокалорий за неделю, то есть примерно сотня в пересчёте на день. Ступень активности же поднимает норму сразу на 300+ ккал **каждый день** и легко съедает больше половины дефицита.

**Отдельного учёта «сожжённого» не будет.** Оценка расхода по шагам врёт на 30–50 %, поверх уже неточного учёта еды, и ошибка эта однобокая: она добавляет разрешённых калорий, то есть тихо гасит дефицит. Разовая прогулка на 700 ккал — это 0,09 кг, меньше разброса от одного неточно записанного обеда. Недельное усреднение на экране статистики закрывает этот случай само.

Если после калибровки большие дни всё-таки захочется учитывать явно, честная минимальная форма — **поправка к норме на конкретный день**, одно число в дне, а не второй счётчик рядом с дневником.

**Всё это требует весов.** Без регулярных взвешиваний цикл не замыкается и норма остаётся догадкой, поэтому график веса из [07-roadmap.md](07-roadmap.md) — не украшение, а недостающая половина калькулятора.

## Пример

Мужчина, 30 лет, 180 см, 85 кг, умеренная активность, мягкое похудение:

```
BMR  = 10×85 + 6.25×180 − 5×30 + 5      = 850 + 1125 − 150 + 5 = 1830
TDEE = 1830 × 1.55                       = 2836.5
цель = 2836.5 × 0.85 = 2411             → 2410 ккал/сутки
```
