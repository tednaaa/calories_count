# 07 — Порядок реализации

Этапы выстроены так, чтобы приложением можно было начать пользоваться как можно раньше, а не после того, как готово всё.

## Состояние

| Этап                           | Статус                                 |
| ------------------------------ | -------------------------------------- |
| 0 — Скелет                     | готово                                 |
| 1 — Данные и каталог           | готово, кроме самих фотографий         |
| 2 — Калькулятор и онбординг    | готово                                 |
| 3 — Экран «Сегодня»            | готово                                 |
| 4 — Экран «Добавить»           | готово                                 |
| 5 — Статистика                 | готово                                 |
| 6 — Настройки, сброс и экспорт | готово                                 |

## Этап 0 — Скелет

Vite + Vue 3 + TypeScript + Tailwind + vue-router. Devenv. Пустые вьюхи, нижняя навигация, `vite-plugin-pwa` в минимальной конфигурации.

**Готово, когда:** `pnpm dev` открывает приложение, переключение по вкладкам работает.

## Этап 1 — Данные и каталог

- `src/entities/food/lib/` — `types.ts`, `categories.ts`, `catalog.ts`.
- `src/shared/db/` — Dexie, схема версии 1, типы `Entry`, `Profile`, `WeightRecord`.
- `src/shared/lib/use-live-query.ts`.
- `src/shared/lib/date.ts` — `toDateKey` и окна дней.
- `scripts/optimize-foods.ts` + `pnpm foods:optimize`.
- `src/entities/food/lib/catalog.spec.ts` — тест целостности каталога.
- Первые 10–15 блюд с реальными фото: то, что реально ешь каждый день.

**Осталось:** сами фотографии. Скрипт сжатия готов, каталог сейчас заполнен заготовкой — калорийность проставлена навскидку, файлов в `public/foods/` нет, поэтому миниатюры показывают фолбэк с первой буквой.

## Этап 2 — Калькулятор и онбординг

- `src/entities/profile/lib/calories.ts` с юнит-тестами на формулу и нижнюю границу.
- `OnboardingView` с живым расчётом.
- Гард роутера по наличию профиля.

**Готово, когда:** первый запуск приводит к сохранённому профилю с нормой.

## Этап 3 — Экран «Сегодня»

Кольцо прогресса, лента дня, редактирование количества, удаление с отменой, переключение на прошлые дни, пустое состояние.

## Этап 4 — Экран «Добавить»

Поиск, чипсы категорий, блок «Часто», сетка карточек, корзина со степперами, подтверждение. Поддержка `?date=` для добавления задним числом.

**Готово, когда:** приложением можно пользоваться по назначению. С этого момента — ежедневная эксплуатация, дальнейшие этапы уже поверх живых данных.

Эксплуатация упирается в фотографии и настоящие калории из этапа 1: сетка сейчас показывает фолбэк с первой буквой, а выбор глазами по фото — основной сценарий экрана.

## Этап 5 — Статистика

Диаграмма за 7 дней с линией цели, сводка, переход на день по тапу.

## Этап 6 — Настройки, сброс и экспорт

Редактирование профиля с пересчётом, ручное переопределение нормы, «Стереть все данные», экспорт и импорт JSON, блок «О приложении», инструкция по установке на iPhone.

Два пункта отсюда не стоит откладывать после начала реальной эксплуатации:

- **редактирование профиля** — до него ошибку в росте или активности нельзя исправить вообще никак, приложение навсегда останется с неправильной нормой;
- **экспорт** — до него единственная копия данных существует в одном экземпляре на телефоне.

## Этап 7 — PWA и деплой

Полный манифест, иконки (192, 512, maskable, apple-touch), мета-теги iOS, прекэш с фотографиями, `navigator.storage.persist()`, `404.html`, `.github/workflows/ci.yml`, кастомный домен, чек-лист из [06-pwa-deploy.md](06-pwa-deploy.md).

**Готово, когда:** приложение установлено на оба телефона и работает в офлайне.

## Открытые вопросы

- **Фотографии и настоящая калорийность.** Каталог остаётся заготовкой: калорийность проставлена навскидку, файлов в `public/foods/` нет, миниатюры показывают фолбэк с первой буквой. Пайплайн готов — `raw-photos/<id>.jpg` плюс `pnpm foods:optimize`.
- **Проверки каталога из [03-catalog.md](03-catalog.md), пунктов 3 и 4** — «файл фотографии существует» и «в `public/foods/` нет осиротевших файлов» — ещё не в тестах. Включать их сейчас нельзя: на заготовке они красят сборку в красный, превращая известное состояние в сломанный билд. Включаются вместе с первыми настоящими фото.
- **Проверка на живом домене.** Чек-лист из [06-pwa-deploy.md](06-pwa-deploy.md) пройдён только локально: сборка отдаёт манифест, `sw.js` с 22 файлами в прекэше и `_redirects`. Установка, офлайн-режим и отступы на iPhone проверяются после первого деплоя.
